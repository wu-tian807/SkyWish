# 第一阶段：外部 Codex → Blender → 游戏资产库

本阶段从 Codex 窗口发起工作。游戏内只提供资产管理入口，不从游戏内调用 Agent；不摆放、不移动、不覆盖现有资产。未来替换实例的方式是移走旧实例、导入独立新资产，再验证空间后摆放。

## 使用入口

1. 启动装有 CityDirector 的 CS2，加载测试城市。
2. Codex 连接 `city_director` MCP。游戏运行时看到右上角“导入资产库”，可查看条目、预览与状态，关闭新导入、隐藏/重新显示，或确认删除资产。
3. Codex 使用本地 Blender 脚本生成模型、贴图、`.blend` 工程和预览图。首轮参考：`node scripts/Build-DemoAsset.mjs`。
4. `director_validate_asset(directory)` 校验 FBX；`director_stage_asset` 保存模型包和来源文件。准备成功后立即进入用户可见的资产列表，尚未导入游戏。
5. `director_import_asset(assetId)` 提交游戏原生导入任务；`director_import_status(assetId)` 查询完成情况。超时或断连后先查同一编号，不创建新任务重试。
6. `director_asset_library` 查看持久化记录和删除状态。`director_archive_asset` 为兼容保留旧名字，实际对应 UI 的隐藏/重新显示；永久删除由用户在游戏 UI 中确认。

本阶段只接收一个静态网格和专属贴图。新编号格式为 `CD_<字母开头的标签><32位UUID>`，标签中不含下划线；目录、FBX、材质名称相同。每次修改分配新的 UUID，可用 `parentAssetId` 记录来源版本。

Codex 的 shell 工具执行 Blender；MCP 负责校验、登记、导入和管理，无需 App Server。当前 MCP 使用标准 STDIO，进程再通过同一 Windows 用户的命名管道连接游戏模组。

## 生命周期与持久化

`asset-library/` 是用户数据，不能当作构建缓存清理：

| 目录 | 内容与用途 |
|---|---|
| `catalog/<id>.json` | 不变编号、名称、来源、校验和、声明的依赖和版本关系 |
| `sources/<id>/` | `.blend`、建模脚本、预览的副本；不是 Agent 原始工作目录 |
| `imports/<id>/` | 校验后的独立 FBX/贴图包；导入前再次核对校验和 |
| `receipts/<id>.json` | 游戏写入的任务预留、完成/失败记录、原生文件位置 |
| `native-backups/<id>/` | 成功后对该资产原生导入目录的文件备份和校验记录 |
| `state/<id>.json` | 可变的隐藏/显示状态，沿用 `archived` 字段 |
| `menus/<id>.json` | 原生建造菜单分类、标题、说明、图标、排序和应用状态；城市加载后重放 |
| `deletions/<id>.json` | 删除进度、失败原因与实际删除文件字节数；成功后可在界面清除记录 |
| `cleanup-runtime/<hash>/` | 从模组复制并校验的清理程序运行副本；不是资产资源，不属于单个资产删除范围 |
| `policy.json` | 用户是否允许新的导入；不强行取消正在执行的原生导入 |

原生导入数据位于游戏用户目录的 `ImportedData/<id>/`，这是游戏实际加载的资产资源。不能假设存档内嵌所有模型和贴图。项目清单也不能替代原生资产文件。

原生导入先写持久化任务预留，再调用游戏接口。同编号重复调用只读取已有任务结果。中途崩溃的任务显示状态未知，保留可能产生的文件，不自动覆盖或重新导入。

“已导入”只表示当前任务检查到 Prefab、实体、几何资源和落盘文件；存档重载与冷启动需要独立实测。资产尚未摆放时，保存/重载只能证明资产库可恢复，不能证明摆放实例的序列化行为。

本阶段的依赖审计仅覆盖自身导入目录，未证明没有共享渲染资源、模板或其他运行依赖。`saveUsage=unknown` 不等于“没有存档引用”。

## 用户控制与移除

- 管理窗口打开时退出当前摆放模式，鼠标、滚轮和快捷键只用于管理窗口。点击“关闭”或按 Esc 返回游戏；继续摆放需重新选择资产，不自动恢复旧预览。关闭按键/鼠标释放后才交还游戏输入。
- 游戏 UI 可查看所有已准备/导入的资产、预览、来源和导入错误；文件路径收进详情。
- 允许导入开关由游戏侧再次检查，Agent 不能通过正常导入接口绕过它。
- “从资产库隐藏”只影响默认列表，阻止该条目继续导入，保留文件；“重新显示”恢复条目。隐藏不会从原生对象浏览器卸载资产或释放空间。
- “删除资产…”显示预计删除的文件大小、范围与存档风险，一次确认后等待游戏进程完全退出，再由独立清理程序执行。当前会话中的实例不会被立即拆除。
- 旧存档依赖未知不阻止删除。当前实例数尚未统计，界面明确显示未知，不把未知伪装成零。
- 删除范围固定为资产库 `imports/<id>`、`sources/<id>`、`native-backups/<id>`、该编号的 catalog/state/receipts/menus，以及游戏 `ImportedData/<id>`。不会读取清单中的任意路径作为删除目标，不碰 Agent 原始 Blender 工程、原始导出、其他资产或存档。
- 不强制归档、回收站或保底副本。删除后只留可清除的小型结果记录；显示的是实际删除文件的逻辑字节数，并非文件系统物理空闲空间的精确变化。
- 正在导入时暂不接受删除，避免生成过程与清理冲突。已提交删除的编号不能再导入或重新准备。
- 清理程序验证目标范围并拒绝符号链接/目录联接，防止删除越过管理边界。部分失败不会回滚或谎报成功，剩余文件可重试；目录条目最后删除。
- 清理程序等待发起请求的进程退出，并检查是否还有其他 CS2 进程。快速重新开游戏会使清理报告失败，用户可再次提交、退出后重试。关机或清理程序意外停止后，也可在资产库重试。
- 0.3.2 起清理程序从资产库内校验过的运行副本启动，避免已观察到的模组安装目录运行时访问失败。等待状态依赖实际工作锁；若程序停止，经过 15 秒启动宽限后转为失败，不再无限显示等待。锁文件仅用于协调，不需要用户手动删除。

磁盘管理由用户负责：可能的引用和未知依赖作为提示，不作为禁止删除的条件。本阶段没有跨资产共享文件清理，范围外的共享资源不会被顺带删除。

## 原生建造菜单（0.3.0）

1. 加载城市后调用 `director_menu_tree`，使用返回的稳定 `categoryId`，不凭中文显示名猜测编号。
2. 用 `director_menu_assets({categoryId, query, offset, limit})` 查询已有条目。结果来自实时注册表，尚未套用界面的主题、内容包等筛选；锁定状态单独返回。
3. 导入完成后调用 `director_assign_asset_category({assetId, categoryId, title?, description?, priority?})`。现有长椅应选择道具类分类；重复设置会去重，换分类会移除旧分类中的条目。
4. 用户可在右上角“导入资产库”选择资产，点击“修改建造菜单分类…”，搜索并选择游戏当前已有的分类。

分类修改无需重新导入模型。配置独立保存，不把其他模组分类引用烘焙进原生资产文件；目标分类缺失时保留配置并报告不可用，分类恢复后重试。游戏版本改变导致菜单刷新接口失配时会报错。

这一版支持已有分类，不创建新的分类/顶层选区，也不修改其他模组资产。分类只决定入口，不能把静态网格变成具备道路、公交等模拟能力的资产。隐藏资产库条目不等于从原生菜单卸载。

## 验收边界

必须分别记录：Blender 导出、MCP 调用、当前城市注册、UI 管理、原生资源备份、菜单重载、进程重启、已摆放实例重载。后一个阶段不能由前一个阶段的成功推定。

实际测试结果见 `VALIDATION.md`。默认不修改已有城市；测试城市使用新建地图、无限金钱和全部解锁。
